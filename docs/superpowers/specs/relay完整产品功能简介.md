# RELAY 产品功能与流程设计

**日期：** 2026-08-17
**状态：** 产品流程已确认
**控制依据：** [RELAY 连续混合助力控制设计](relay连续混合助力设计.md)

## 1. 产品定义

RELAY 是面向下肢骨科术后院后恢复期的坐行一体康复设备。

> 医生设定康复边界，Agent 每天整理建议，设备在坐站和步行中实时补力，并把有价值的进展与异常反馈给医生。

### 目标患者

- 已获医生允许完全负重或按耐受负重；
- 能主动起立和迈步，但仍存在力量不足、负重不对称或稳定性下降；
- 主要包括髋部骨折、髋/膝关节置换和获准负重的下肢骨折术后患者。

首版不覆盖禁止负重、需要严格机械减重、不能主动迈步或需要关节级步态驱动的患者。腰椎术后属于后续研究范围。

## 2. 核心角色

| 角色 | 核心职责 |
|---|---|
| 医生/康复师 | 确认处方、允许任务、负重方式、剂量和停止条件；处理异常并更新处方 |
| 患者 | 确认当日状态、选择任务、主动发起动作并随时停止 |
| 设备 | 实时测量、按需助力、主动跟随、安全保护和数据记录 |
| Agent | 整理每日建议、解释有效变化、筛选异常和生成复诊摘要 |
| 照护者 | 按需完成穿戴、症状、环境和联系医生等人工任务，非核心功能 |

控制权限遵循：

```text
急停与硬件保护
> 机械锁止与安全监督
> 医生确认的处方
> 患者停止指令
> 实时任务控制
> Agent建议
```

Agent 不修改处方、不诊断疾病，也不直接控制座椅扭矩或轮速。

## 3. 核心功能

| 功能 | 产品输出 | 主要使用者 |
|---|---|---|
| 处方管理 | 结构化任务、剂量、负重和停止边界 | 医生、设备 |
| 个人适配 | 座椅/扶手位置、传感器校准和安全助力基线 | 康复师、患者 |
| 每日康复建议 | 处方内、简短且个性化的当日行动建议 | 患者 |
| 主动坐站 | 患者发起后提供最低必要旋转座椅助力 | 患者 |
| 受控坐下 | 根据下降速度提供承托和吸能 | 患者 |
| 主动跟随步行 | 根据扶手意图跟随、转向和减速 | 患者 |
| 坐姿电动运输 | 完成室内生活移动，不计入康复 | 患者 |
| 康复监测 | 有效剂量、机器助力、患侧参与、代偿和疲劳趋势 | 患者、医生 |
| 异常证据包 | 异常事实、持续时间、基线变化和数据质量 | 医生 |
| 复诊摘要 | 一页式康复趋势和待决策问题 | 医生 |

## 4. 整体流程

```mermaid
flowchart LR
    A["医生设定处方"] --> B["设备完成个人适配"]
    B --> C["Agent生成每日建议"]
    C --> D["患者进行康复或坐姿运输"]
    D --> E["设备实时助力并记录表现"]
    E --> F["异常提醒医生，复诊更新处方"]
    F --> C
```

### 第一步：医生设定边界

医生确认：

- 诊断、术式、患侧和负重许可；
- 允许的坐站、步行和运输任务；
- 次数、时长、距离和速度范围；
- 疼痛、RPE、禁忌和停止条件；
- 处方有效期和复诊时间。

自然语言病历可由 Agent 整理成候选字段，但必须经医生确认后才能生效。

### 第二步：设备完成个人适配

首次使用或处方显著变化后完成：

- 座椅高度、扶手高度和脚位适配；
- 鞋垫、座面压力、扶手力、IMU和摄像头校准；
- 座椅自重、摩擦、扭矩和左右轮反馈标定；
- 在专业人员监督下建立安全助力和动作基线；
- 检查家庭地面、门槛、通道和转向空间。

### 第三步：Agent 整理每日建议

Agent 综合有效处方、最近安全参数、近期表现、疲劳、疼痛和当日状态，只输出会改变当天行动的信息，例如：

- 延续当前安排；
- 在处方内降低当日剂量；
- 使用更保守的初始助力；
- 暂缓训练并重新确认症状；
- 请求医生或康复师复核。

前台建议可自由组织，不使用固定模板；后台保留处方版本、数据来源、时间范围、置信度和生成原因。

### 第四步：患者主动完成任务

患者选择两种模式之一：

#### 康复模式

- 主动坐站和受控坐下；
- 室内主动跟随步行；
- 患者确认并主动发起后，设备才提供按需助力；
- 实时控制和安全保护全部在本地执行。

#### 坐姿运输模式

- 用于卧室、卫生间、客厅等室内移动；
- 使用独立速度和安全规则；
- 不计入康复剂量，不更新下肢康复能力。

### 第五步：记录、异常和复诊

系统只把数据质量合格的动作计入康复记录，包括：

- 有效坐站次数和步行剂量；
- 座椅实际助力；
- 患侧参与和左右负荷；
- 扶手与姿态代偿；
- 心率、疲劳、疼痛和停止原因。

正常数据用于更新个人基线；只有影响行动的变化才向患者解释。异常整理成证据包进入医生队列，复诊前自动生成一页摘要。医生确认新处方后进入下一轮。

## 5. Agent 辅助输出

Agent 只保留边际效用较高的四项输出：

1. **每日康复建议：** 帮助患者决定今天做什么、是否降低剂量或暂停；
2. **必要的训练后解释：** 只说明有效变化和下一步注意事项；
3. **异常证据包：** 把原始数据压缩成医生可以处理的事实；
4. **复诊前一页摘要：** 让医生快速了解趋势和待决策问题。

照护者只在需要人工处理时收到任务，例如穿戴检查、疼痛确认、环境清理或联系医生。

不提供持续语音陪练、复杂患者仪表盘、康复排名、自动诊断或自动修改处方。

## 6. 数据与监测

### 实时控制数据

- 双侧压力鞋垫；
- 四点座面压力；
- 左右扶手多轴力；
- 腰骶、患侧大腿和小腿 IMU；
- 座椅角度、扭矩和左右轮速度。

### 辅助监测数据

- 本地摄像头提取的姿态特征；
- 心率、RPE、疼痛和疲劳趋势；
- 腰部以下局部温度趋势。

原始视频不上传；姿态特征可以进入每日记忆并供医生参考。心率、温度和 Agent 不进入实时电机控制。局部温度只能用于趋势观察，不能用于自动诊断感染或血栓。

### 每日个人记忆

每日更新最近安全助力、动作与姿态基线、患侧参与、扶手代偿、疲劳趋势和异常记录。数据不足时回到康复师确认的保守参数。

运输数据可用于设备和生活移动记录，但不得更新康复能力。

## 7. 异常处理

异常输出不直接给出诊断，而是说明：

```text
发生了什么
+ 持续多久
+ 与个人基线相比变化多少
+ 数据是否可靠
+ 患者是否确认症状
+ 当前处方要求如何处理
```

| 对象 | 只接收的信息 |
|---|---|
| 患者 | 暂停、重新确认、继续观察或联系医生等行动建议 |
| 照护者 | 必须人工完成的检查和联系任务 |
| 医生 | 需要临床判断的异常证据包 |

正常数据不发送给医生，避免告警疲劳。关键传感器、执行器或制动故障由本地安全系统处理，不等待 Agent 或医生响应。

## 8. 功能边界

产品可以表述：

> RELAY 在医生处方范围内，为患者的坐站和室内步行提供连续按需助力，并把有价值的康复表现和异常整理给医生。

产品不能表述：

- 自动制定或修改医疗处方；
- 判断骨愈合或直接测量骨/植入物载荷；
- 保证不跌倒、加快骨愈合或减少再入院；
- 已证明优于常规康复；
- 患者离开座面后仍提供持续体重减重；
- 助力越少就一定代表康复越好。

## 9. 首版优先级

### 核心功能

- 处方管理与版本控制；
- 个人适配与传感器校准；
- 主动坐站、受控坐下和主动跟随步行；
- 坐姿电动运输及训练数据隔离；
- 每日康复建议；
- 有效训练记录、异常证据包和复诊摘要；
- 本地安全、故障降级和完整审计。

### 非核心功能

- 照护者人工任务提醒；
- 通用健康问答、陪伴和持续激励；
- 复杂可视化仪表盘；
- 轮端主动抗阻；
- 腰椎术后和重度神经损伤适应证。
